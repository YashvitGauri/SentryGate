# The paper

The paper is written while the work happens, not at the end.
This folder holds it.

| File | What it is |
|---|---|
| `paper.md` | The paper itself. Sections fill in as the code makes them true. |
| `lab-notebook.md` | One entry per week. What we did, what broke, what the numbers were. |
| `related-work.md` | Reading list. Every claim we make about other people's work is sourced here first. |
| `figures/` | Charts. All generated by `eval/make_figures.py`, never drawn by hand. |

## The rule

Nothing goes in `paper.md` unless something in the repo already makes it true.

- A number must come from a committed script and a log file.
- A design claim must point at the file that implements it.
- Anything not yet earned is marked `TODO(week N)` and says what evidence it needs.

This is why the paper cannot drift from the system.
It is the same rule the Phase 1 deck already follows, where every slide number is parsed from a recorded run.

## Weekly habit

At the end of each week, in this order:

1. Add the week's entry to `lab-notebook.md`. Raw and honest, including dead ends.
2. Move anything now proven out of the notebook and into `paper.md`.
3. Delete the `TODO(week N)` markers that the week just cleared.

Step 1 takes ten minutes and makes steps 2 and 3 possible.
Skipping it is how a paper ends up being written from memory in November.
